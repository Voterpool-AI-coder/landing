## MODIFIED Requirements

### Requirement: Карточки моделей консенсуса отражают точную математику docs/02

Секция «Math» лендинга ДОЛЖНА показывать для каждой из трёх моделей условия PASSED/REJECTED/EXPIRED, совпадающие с docs/02 §1.4:

- MAJORITY — PASSED при `Y > T/2`; REJECTED при `N ≥ T/2` или таймауте; EXPIRED невозможен; примечание ДОЛЖНО описывать неявку как голос «против» от полной силы T и НЕ ДОЛЖНО утверждать наличие варианта ABSTAIN.
- QUORUM_PERCENTAGE — PASSED при `V ≥ Qreq ∧ Y > N`; REJECTED при `V ≥ Qreq ∧ N ≥ Y`; EXPIRED при недоборе кворума к моменту истечения времени; примечание сохраняет смысл «не проголосовавший не учитывается нигде».
- CONSENT — трактовка «полный круг согласия»: PASSED при `N = 0 ∧ Y > 0 ∧ C ≥ H`; REJECTED при любом `N > 0`; EXPIRED при незамкнутом на таймауте круге, формула EXPIRED: `timeout ∧ (C < H ∨ Y = 0)` (равносильно `timeout ∧ ¬PASSED ∧ ¬REJECTED`), включая случай «все воздержались» (Y = 0, N = 0); карточка ДОЛЖНА указывать допустимость только `power_distribution = EQUAL`.

Легенда переменных над карточками ДОЛЖНА определять все символы, используемые в формулах, включая `C` (число проголосовавших) и `H` (замороженное на момент создания предложения число ACTIVE-участников), а также `Y`, `N`, `V`, `Qreq`, `T`.

Компромисс с `landing-messaging`: каждая карточка ДОЛЖНА содержать точную формулу как технический якорь И рядом — читаемое описание на английском (plain-English), плюс ссылку на полную спецификацию (openspec). Формула-якорь обязательна для воспроизводимости; plain-English — для доступности.

#### Scenario: Посетитель читает карточку CONSENT

- **WHEN** посетитель открывает секцию «Math» лендинга
- **THEN** карточка CONSENT показывает условие PASSED `N = 0 ∧ Y > 0 ∧ C ≥ H`, условие EXPIRED `timeout ∧ (C < H ∨ Y = 0)` (покрывающее случай «все воздержались», Y = 0), и содержит указание, что модель доступна только с EQUAL

#### Scenario: Посетитель читает примечание MAJORITY

- **WHEN** посетитель читает примечание под карточкой MAJORITY
- **THEN** примечание объясняет, что неявка считается голосом «против», и не содержит утверждения об учёте воздержания (ABSTAIN) как «нет»

#### Scenario: Легенда покрывает символы формул

- **WHEN** посетитель сверяет формулы карточек с легендой
- **THEN** каждый символ, встречающийся в формулах (Y, N, V, Qreq, T, C, H), определён в легенде

#### Scenario: Карточка содержит якорь-формулу и plain-English описание

- **WHEN** посетитель читает любую карточку модели консенсуса
- **THEN** карточка показывает точную формулу-якорь рядом с читаемым описанием на английском и ссылкой на полную спецификацию openspec

## ADDED Requirements

### Requirement: Hero-статистика показывает ровно 18 инструментов протокола

Hero-статистика `components/HeroClient.tsx` (метрика «decision lifecycle calls over MCP») ДОЛЖНА отображать значение `18`, соответствующее каноническому подсчёту инструментов протокола (register_agent, whoami, update_agent, get_agent, create/join/leave/transfer/dissolve/list_pending, create_proposal, cast_vote, server/discover, tools/list, get_playbook, get_proposal, get_proposals, wait_proposal_close). Значение `20` или любое иное ДОЛЖНО быть заменено на `18`.

#### Scenario: Посетитель видит hero-статистику инструментов

- **WHEN** посетитель загружает лендинг и читает hero-статистику
- **THEN** метрика «decision lifecycle calls over MCP» показывает число `18`, а не `20`

### Requirement: Текст о шардировании отражает Stage 1 standalone и будущие shard-seams

Любой видимый текст лендинга, упоминающий шардирование или горизонтальное масштабирование, ДОЛЖЕН соответствовать `canonical-specs/shard-seams`: на Этапе 1 допустимо только `cluster.mode: standalone` (любое иное значение — fail-fast; отсутствие секции эквивалентно standalone). Шардирование ДОЛЖНО описываться как будущий интерфейсный «шов» (порты IDirectory/IIdentity/IEventBus), а не как текущее runtime-поведение. Запрещено утверждать, что шардирование «происходит» прямо сейчас за round-robin балансировщиком.

#### Scenario: Посетитель читает текст о шардировании

- **WHEN** посетитель читает раздел, упоминающий шардирование/масштабирование
- **THEN** текст описывает stateless-ядро как спроектированное для будущего масштабирования через shard-seams и не утверждает, что шардинг уже выполняется за round-robin балансировщиком
