# Design: sync-landing-copy-with-docs

## Context

Весь копирайтинг лендинга живёт в двух файлах: `app/page.tsx` (массивы `features`, `CONSENSUS_MODELS`, `STACK_LAYERS`, `guarantees`, `QUICKSTART_LINES` + инлайн-тексты секций) и `components/Terminal.tsx` (`SCENES`). Компоненты `HeroClient`, `HowItWorks`, `Header`, `ContactForm` факты не искажают и вне скоупа, кроме выборочной проверки. Источник истины — текущая редакция `docs/` (см. proposal.md — Why). Сайт статический (Next.js App Router → `out/`), бэкенда нет, поэтому «поведение» здесь — это содержимое отрендеренного HTML.

## Goals / Non-Goals

**Goals:**

- Устранить каждое фактическое расхождение текст ↔ docs, найденное при сверке (перечислены в proposal.md — What Changes).
- Сохранить существующий тон, структуру секций, вёрстку и анимации — меняются только строки данных и мелкие формулировки.
- Сделать демо-терминал воспроизводимым по docs/05 §1.0: скопировав сцену в реальный curl, агент получил бы корректный ответ.

**Non-Goals:**

- Новые секции/карточки «про всё новое» из новой редакции (get_playbook, `_meta`-канал, лимиты вступлений упоминаются точечно внутри существующих текстов, а не отдельными блоками).
- Редизайн, изменение layout.tsx-метаданных, i18n, изменение стека лендинга.
- Синхронизация README.md самого лендинга (он описывает сайт, а не Voterpool).

## Decisions

1. **Правки в массивах данных, без нового слоя контента.** Альтернатива — вынести все строки в отдельный `content.ts`/JSON для будущих синков — отклонена: увеличивает диф и риск регрессий вёрстки; единый словарь имеет смысл, если синк станет регулярным (отмечено в Risks).
2. **Терминал показывает только режим A (`tools/call`).** Mode B задепректирован (docs/05 §1.0: «новые агенты должны использовать режим A»), демонстрировать его нельзя. Тело сцены сокращаем до валидного минимума: `{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":…,"arguments":{…}}}`; `clientInfo` в примерах опускаем (опционален) ради длины строк. Заголовки каждой сцены: `MCP-Protocol-Version: 2026-07-28`, `Mcp-Method: tools/call`, `Mcp-Name: <tool>`; `Authorization: Bearer …` — во 2-й и 3-й сценах, в 1-й (`register_agent`) отсутствует намеренно.
3. **Формулы — юникодом в существующем стиле** (`∧ ≥ ∨`), новые переменные `C`, `H` добавляются одной строкой легенды; карточка CONSENT получает подзаголовок «Full circle of consent» вместо «Absence of objections». Альтернатива — рисовать KaTeX/MathJax — отклонена: новая зависимость ради трёх строк.
4. **«Backup-ready» переписывается, а не удаляется.** Гарантия остаётся карточкой: консистентный point-in-time снапшот одной командой `voterpool checkpoint`; про downtime формулировка меняется на честную («runs against a stopped engine or an offline copy of the data directory»).
5. **Строку quickstart `./build.sh --yes` сохраняем.** Процедура сборки в `docs/` не описана (там только CMake/vcpkg-манифест), прямого противоречия нет; команды сборки — зона апстрим-README, недоступного в этом репозитории. Записано как допущение.
6. **Проверка результата**: `yarn lint`, `npx tsc --noEmit`, `yarn build` + построчная вычитка изменённых мест против docs/02 §1.4, docs/05 §1.0–1.7, docs/06 §1.3, docs/13 §3.

## Risks / Trade-offs

- [Длинные curl-строки ломают визуал терминала (печать 9–29 мс/символ, `whitespace-pre`)] → заголовки переносятся `\`, JSON ужимается до минимума, сцены прогоняются в dev-режиме до/после; при необходимости снизить скорость печати первых сцен.
- [Маркетинговый тон конфликтует с инженерной точностью] → правки формулируются как уточнение терминов, а не юридические оговорки; каждая фраза должна быть воспроизводима по конкретному разделу docs.
- [`docs/` игнорируется git'ом и обновится снова] → дельта-спека фиксирует соответствие «текст = редакция docs» как требование; повторный синк — новый прогон этого же чейнджа по свежему дифу.
- [Часть утверждений не покрывается docs (build.sh, порт 8080 подтверждён docs/08)] → такие места не трогаем; правило «меняем только при прямом противоречии».

## Migration Plan

Обычный CI-деплой: merge в `main` → GitHub Pages получит пересобранный `out/`. Откат — `git revert` коммита с правками; состояния и данных у сайта нет.

## Open Questions

Нет блокирующих. Единственное записанное допущение — сохранение `./build.sh --yes` в quickstart (решение 5); его можно переоткрыть, если появится доступ к актуальному README апстрима.
